Напиши в файле `solution.py` мини-СУБД на чистом Python без внешних библиотек. Один файл.

API ровно такое:
1. `Database(path=None)`. Если `path` передан — данные переживают закрытие и повторное открытие. Если нет — база живёт в памяти.
2. `db.begin()` возвращает объект транзакции.
3. `tx.insert(table: str, row: dict) -> int` — вставляет строку, возвращает её `_id`. Таблица создаётся при первой вставке. В возвращаемых строках всегда есть `_id`.
4. `tx.select(table: str, where: dict | None = None) -> list[dict]` — строки, подходящие по точному совпадению всех пар `where`. Порядок — по возрастанию `_id`. Возвращаются копии: изменение результата не меняет базу.
5. `tx.update(table: str, where: dict, changes: dict) -> int` — число изменённых строк. `_id` менять нельзя: `ValueError`.
6. `tx.delete(table: str, where: dict) -> int` — число удалённых строк.
7. `tx.commit()` и `tx.rollback()`. После любого из них транзакция мертва: любой вызов, кроме чтения, поднимает `RuntimeError`.
8. Изоляция — снимок на момент `begin()` плюс собственные записи транзакции. Чужие коммиты после начала не видны.
9. Конфликт: если строка, которую транзакция меняет или удаляет, была изменена чужой зафиксированной транзакцией после начала этой — `commit()` поднимает `ConflictError`. Класс `ConflictError` должен быть в модуле.
10. Долговечность: `commit()` пишет журнал на диск до применения к памяти. После `db.close()` и повторного `Database(path)` все зафиксированные данные на месте.
11. Журнал append-only. Повреждённая последняя запись (обрезанная строка, мусор в конце) при открытии игнорируется, всё, что было зафиксировано раньше, сохраняется.
12. `db.close()` идемпотентен.
13. `_id` уникален в пределах базы и никогда не переиспользуется.
14. Данные — любые JSON-совместимые значения, включая юникод.

Верни файл `solution.py`.
