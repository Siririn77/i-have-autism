```
python3 -c "from m import avg; avg([])"   # ZeroDivisionError: division by zero
```

Нет, не всё в порядке. Первую команду я не запускал; её вывод следует из `len([]) == 0`. «Тесты зелёные» означает, что тесты не проверяют пустой вход, а не что функция верна.

Что не так, по убыванию важности:

1. Пустой список: `len(xs) == 0` → деление на ноль. Сообщение называет операцию, а не причину; вызывающий не узнаёт, что вход был пуст.
2. Контракт на пустом входе не выбран. Это решение, не деталь. Цена каждого варианта:
   - `raise ValueError("avg: пустой список")` — ошибка видна в точке возникновения; цена: каждый вызов обязан её обработать или упасть.
   - вернуть `None` — вызывающий должен помнить проверку; в арифметике даст `TypeError` через несколько слоёв, не здесь.
   - вернуть `math.nan` — не падает, но nan проходит через все последующие суммы молча, и `nan == nan` даёт `False`.
3. Точность на float: `sum` накапливает ошибку округления. `math.fsum(xs) / len(xs)` даёт точную сумму. Для int разницы нет.
4. Имя `xs` не говорит, что нужна последовательность чисел. `sum` принимает любой iterable, `len` требует sized: генератор пройдёт `sum` и упадёт на `len`.
5. `bool` — подкласс `int`: `avg([True, False])` вернёт `0.5` молча.

Минимальная правка:

```python
import math

def avg(xs):
    if len(xs) == 0:
        raise ValueError("avg: пустой список, среднее не определено")
    return math.fsum(xs) / len(xs)
```

Тест, которого не хватало:

```python
def test_avg_empty_raises():
    with pytest.raises(ValueError, match="пустой список"):
        avg([])
```

Один вопрос: какой контракт на пустом входе тебе нужен — `ValueError` (рекомендую), `None` или `nan`? От ответа зависят сигнатура и тест.
