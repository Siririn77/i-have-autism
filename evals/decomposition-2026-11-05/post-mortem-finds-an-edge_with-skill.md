```
python -c "from x import avg; avg([])"
```
→ `ZeroDivisionError: division by zero` в строке `sum(xs) / len(xs)`.

Не в порядке. Причина: `len([]) == 0`, деление на ноль. Тесты зелёные, потому что ни один тест не передаёт пустой список — это пропущенный шаг, а не случайность.

Граф, 3 узла:
- **Пустой вход.** Что: `len(xs) == 0` в знаменателе. Почему важно: единственный вход, который ломает функцию на каждом вызове. Якорь: `len(xs)`. Когда: всегда, если вызывающий не проверил до вызова.
- **Контракт пустого входа.** Что: `raise` / `nan` / `None`. Почему важно: это решает вызывающий, а не `avg`; молчаливый `nan` расползётся по арифметике. Якорь: строка `if not xs`. Когда: до первого вызова с пустым списком.
- **Тест на пустой вход.** Что: `pytest.raises(ValueError)`. Почему важно: зелёный прогон без него ничего не говорит о границе. Якорь: `tests/test_avg.py`. Когда: в этом коммите.

Стандартная библиотека решает так же (`statistics.mean([])` → `StatisticsError`), поэтому по умолчанию делаю `raise`, стоимость: вызывающий обязан ловить:

```python
def avg(xs):
    if not xs:
        raise ValueError("avg: пустой список, среднего нет")
    return sum(xs) / len(xs)
```

Проверка:
1. `avg([])` → `ValueError` с этим текстом.
2. `avg([2, 4])` → `3.0`.
3. `pytest` — зелёный, включая новый тест.

Две вещи рядом, не правлю (одна причина каждая):
- Генератор вместо списка: `sum` его съест, `len` упадёт с `TypeError`. Сигнатура обещает список.
- `avg` от `int` больше ~1.8e308 даёт `OverflowError` на делении. Дубликаты и не-ASCII не ломают: вход — только числа.

Следующее действие: добавь тест `avg([])` → `ValueError`, прогони `pytest`, сдавай.
