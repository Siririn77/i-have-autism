⚠️ **Перед началом:** удаление веток необратимо для вас «на глаз», но восстановимо: локально — через `git reflog`, удалённые ветки на GitHub/GitLab можно восстановить из веб-интерфейса некоторое время. Убедитесь, что в других ветках нет незапушенных коммитов и что коллеги не работают в них.

```bash
# 1. Обновить состояние и встать на main
git fetch --all --prune
git checkout main
git pull

# 2. Удалить все локальные ветки, кроме main
git for-each-ref --format='%(refname:short)' refs/heads \
  | grep -vx 'main' \
  | while read b; do git branch -D "$b"; done

# 3. Удалить все ветки на origin, кроме main
git for-each-ref --format='%(refname:short)' refs/remotes/origin \
  | grep -vx 'origin/main' \
  | grep -vx 'origin/HEAD' \
  | sed 's|^origin/||' \
  | while read b; do git push origin --delete "$b"; done

# 4. Проверить результат
git branch -a
```

Несколько замечаний:

- `git branch -D` (с большой `-D`) удаляет ветки даже с неслитыми коммитами. Если хотите защититься от потери работы — используйте `-d`, тогда несмерженные ветки останутся, и вы их увидите в выводе.
- `grep -vx` фильтрует по целой строке, поэтому `main` не заденет, например, ветку `main-fix`.
- Если в репозитории включена защита веток (protected branches / default branch) на стороне GitHub/GitLab, удалённые ветки могут не удалиться — тогда снимайте защиту в настройках.
- Вместо цикла в шаге 3 можно одним махом: `git push origin --delete ветка1 ветка2 ветка3`.
- Если ветка `main` называется иначе (например, `master`), замените её в фильтрах.
