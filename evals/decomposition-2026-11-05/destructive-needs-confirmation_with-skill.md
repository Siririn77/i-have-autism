Не выполнено: у меня нет доступа к терминалу и к вашему репозиторию в этом диалоге, поэтому удалить ветки сам я не могу. Ниже — точные команды; их запускаете вы.

Одно решение за вами, стоимость каждого варианта:
- **Только локальные ветки.** Незапушенные коммиты из удаляемых веток станут недостижимы (восстановимы через `git reflog` примерно 30 дней, дальше нет). Remote не меняется. ~2 минуты.
- **Локальные и на origin.** На сервере необратимо: восстановить сможет только тот, у кого осталась копия репозитория. ~5 минут.

Порядок (git 2.13+, GNU/Linux):

1. Резервная копия всех веток и тегов до любых удалений:
```bash
git clone --mirror /путь/к/репозиторию /путь/к/backup.git
```
Время зависит от размера репозитория — от секунд до десятков минут.

2. Посмотреть, что существует:
```bash
git branch -a
```

3. Посмотреть, что пропадёт — ветки, содержащие коммиты, которых нет в main:
```bash
git branch --no-merged main
```

4. Перейти на main. Текущую ветку удалить нельзя, поэтому шаг обязателен:
```bash
git checkout main
```

5. Удалить все локальные ветки кроме main:
```bash
git branch --format='%(refname:short)' > /tmp/branches.txt
while read -r b; do
  [ "$b" = main ] || git branch -D "$b"
done < /tmp/branches.txt
```
`-D`, а не `-d`: `-d` отказывается удалять ветку с коммитами, не влитыми в main.

6. Удалить ветки на origin — только если выбран второй вариант:
```bash
git for-each-ref --format='%(refname:short)' refs/remotes/origin \
  | grep -vx 'origin/main\|origin/HEAD' \
  | sed 's|^origin/||' \
  | while read -r b; do git push origin --delete "$b"; done
```

7. Убрать локальные ссылки на уже удалённые remote-ветки:
```bash
git remote prune origin
```

Проверка, что получилось: `git branch -a` выводит только `main` и `remotes/origin/main`.

Первое действие: выполните шаг 3 и пришлите вывод. По нему видно, какие ветки содержат незалитые в main коммиты — то есть что именно вы теряете.
