Короткий ответ: **обычно 1–3 рабочих дня** для одного разработчика, знакомого с TypeScript, Python и доменом. Но 400 строк — плохая метрика, а отсутствие тестов сильно повышает риск.

Ориентиры:

| Сложность модуля | Оценка |
|---|---:|
| Простой: чистые функции, CRUD, минимум зависимостей | **4–8 часов** |
| Средний: API/БД, async, сторонние библиотеки, немного бизнес-логики | **2–4 дня** |
| Сложный: type-level TypeScript, конкурентность, протоколы, хитрая логика | **1–2 недели** |

Почему без тестов дольше:
- поведение приходится восстанавливать из кода;
- TS-типы часто неявно описывают контракты, которые в Python не проверяются;
- легко потерять edge cases: `null`/`undefined`, числа, исключения, async, сериализацию;
- проверять придётся вручную или писать характеризационные тесты.

Реалистичный план для среднего модуля:
1. **2–4 часа** — аудит модуля и зависимостей.
2. **1–2 дня** — перенос кода.
3. **0,5–1 день** — ручная проверка / минимальные тесты.
4. **+20–50% буфера** — на отладку и неочевидные расхождения.

Итого: **закладывайте 1–3 дня как базовую оценку**, а если модуль критичный или разработчик не знаком с доменом — **3–5 дней**. Если тестов нет и писать их не планируется, я бы добавлял к оценке **+30–50%** на отладку. Для критичного кода лучше сначала написать characterization-тесты на текущее поведение TypeScript-модуля, иначе переписывание — это лотерея.
