Нет, хранить деньги в `float` — плохая идея.

Причина: `float`/`double` — двоичная плавающая точка, и многие десятичные суммы вроде `0.10`, `0.20`, `1.15` не представляются точно. Из-за этого возникают ошибки округления, которые накапливаются при сложении, вычитании, расчёте процентов, налогов, скидок и сравнениях.

Примерно так:
```python
0.1 + 0.2 == 0.3  # False
```
В деньгах такие расхождения недопустимы.

Как лучше:

1. **Хранить сумму в целых минимальных единицах** — копейках, центах:
   ```python
   1250  # вместо 12.50 руб.
   ```
   Или в Python использовать `Decimal`:
   ```python
   from decimal import Decimal
   amount = Decimal("12.50")
   ```

2. **В БД** использовать `DECIMAL/NUMERIC` с фиксированной точностью, например `NUMERIC(15, 2)`, а не `FLOAT/DOUBLE`.

3. **Явно задавать правила округления** — когда и до скольких знаков округлять.

Итого: `float` можно использовать для приблизительных расчётов, но не для хранения и учёта денег. Для денег — целые копейки/центы или decimal-тип с фиксированной точностью.
