## Где правила проигрывают

Три кейса с правилами 2 из 3, а не 3 из 3: `disagree-first-line`, `scope-stays-scope`, `unknowns-are-marked`.
В них правило требует жёсткой формы (возражение первой строкой, отчёт о соседнем дефекте, пометка о нехватке данных),
и модель иногда проскакивает мимо формы, оставаясь по смыслу правой. Это не провал правил, но и не шум —
это место, где формулировку стоит заострить.

## Как читать артефакты

Для каждого кейса два файла: `_without-skill.md` и `_with-skill.md`. Разница видна глазами, а не только по счёту.
`report.json` хранит все ответы и все пробы; `cases.json` и `run_evals.py` лежат рядом, чтобы прогон повторялся из этого каталога.

## Две ловушки, в которые этот прогон уже попал

1. **Маленький бюджет токенов читается как провал правила.** Модель тратит токены на рассуждение до того, как пишет: при `max_tokens` ниже примерно 2500 ответ приходит пустым с `finish_reason: "length"`. Раннер повторяет запрос с двойным бюджетом и потом падает громко. Пустой ответ — сломанный вызов, а не проваленный кейс.
2. **Одна проба — шум.** Даже при `temperature: 0` ответы расходятся. По умолчанию три пробы на плечо и решение по большинству; `--repeat 1` годится только для отладки.

## Воспроизвести

```bash
python3 evals/run_evals.py --repeat 3
python3 evals/run_evals.py --id decomposition-huge
```

Ключ берётся из `$OLLAMA_API_KEY` или из `/root/.hermes/profiles/ougi/.env`. Код выхода 1, если плечо с правилами не обошло базовое плечо или если хоть один вызов упал.
