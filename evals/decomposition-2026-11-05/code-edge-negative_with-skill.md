```python
def take(xs, n):            # было: head(xs, n)
    if n < 0:
        raise ValueError(f"n={n}, ожидалось n >= 0")
    return xs[:n]
```

Три дефекта, по убыванию:

1. **`n < 0` тихо делает другую операцию.** `head([1,2,3], -1)` → `[1, 2]`; `head([1,2,3], -10)` → `[]`. Ошибки нет, результат выглядит правдоподобно. Вызывающий код получает неверные данные и не узнаёт об этом. Это главное: молчаливый неверный результат хуже падения.
2. **Имя `head` означает не это.** В Haskell, OCaml, Erlang, Prolog `head` возвращает первый элемент, а не срез, и принимает один аргумент. Читатель вызовет `head(xs, 3)`, ожидая `xs[0]`. Имя, которому нужен комментарий, — неверное имя (правило 14). Верное: `take`.
3. **`n > len(xs)` возвращает меньше `n` элементов без сигнала.** Это дефект только если контракт требует ровно `n`. Контракт нигде не записан — вот это и есть дефект: нельзя сказать, ошибка это или норма. `[?]`

Не дефекты: `n = 0` → `[]`, пустой `xs` → `[]`, для `str`/`bytes`/`tuple` возвращается тот же тип. Всё три — корректное поведение среза.

Отдельно, не в диффе: `xs[:n]` копирует. Для `n` порядка `10**9` это гигабайты; если нужен именно срез без копии, функция не подходит.

Проверка после правки:

```python
take([1,2,3], 2)    # [1, 2]
take([], 5)         # []
take([1,2,3], -1)   # ValueError: n=-1, ожидалось n >= 0
```

Следующее действие: переименовать `head` → `take` во всех местах вызова и добавить guard на `n < 0`.
