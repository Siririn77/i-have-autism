# 0.16.0 — checks with teeth, claims with sources, reports with the damage first

Three rules, each bought with a specific failure from the same day.

## 30. A check you have not seen fail is not a check

Three times a stand reported a model failure that was the stand's own: a drawn graph parsed as code, a
test suite taken for the solution, prose imported from an unlabelled fence. Every time the check was
green because it checked the wrong object.

`tools/checks.json` declares, per check, an input that must pass and an input that must fail.
`tools/check_teeth.py` runs both and stops if the bad input passes. Adding a check now means adding a
pair and a reason.

## 31. A claim enters the text with work, journal, year and status

Twice in one day the figure was right and the journal was wrong: +46 % belongs to *Lancet Planetary
Health* and was attributed to *PNAS*. Every word-level check passed, because the words were there.

`tools/claims.py` reads a ledger table and fails on a missing cell, a year in words, an invented status,
a source that is not a domain. Its limit is stated in the skill: it cannot know a journal is the wrong
journal — it can only demand that one is named.

## 32. A report starts with what broke

A report said the graph made the model stop writing; the model had hit a token ceiling.

New eval check type `before`: the first mention of a failure must precede the first mention of success.
Case `report-failure-first`: baseline 1/3, rules 2/3 — an arm verdict of pass, and a delta of one sample
out of three. Not a guarantee, and not reported as one.

Two defects in this rule's own measurement, both found after the first run and both worth keeping:

- the first run's arm verdict was a fail while one sample of two had passed: with two samples a tie
  reads as a fail, and the console printed `rules 0/1`. The claim "1/2, so it works" was wrong;
- the check that required the word `бюджет` rejected the better answer, which said `лимит 6000 токенов`
  and separated the completion limit from the prompt limit. A pattern test failing a correct answer is the
  third instance of the same defect in two days; the check is now a single regex over five words.

## Also

`tests/test_evals.py` no longer keeps its own list of check types — it reads them from the runner. The
hand-kept list had already fallen five types behind.
