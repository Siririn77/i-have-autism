Release 0.4.0: the decomposition plan

## What this adds

A rule the whole set was missing: **before any work, write the plan** — to a file, sized to the task.

- **D1. The plan comes first, as a file.** `plan.md` next to the work; the chat is not a file. Research to *write* the plan is allowed (reading, listing, one `--help`); anything that changes state is not.
- **D2. The plan's size is the task's size.** One-shot script: 2-3 lines in the reply. Several files: 60-120 lines. Film, course, series, book: 500-1000+ lines, plus a plan per part. When in doubt, size by the number of irreversible steps, not by the number of files.
- **D3. Ten sections of a full plan:** goal and an observable definition of done, out of scope, inputs with a check for each, units of work, input -> action -> output -> verification per unit, dependency order and critical path, risks with a trigger and a reaction, blocking gates, estimates in minutes, drift log.
- **D4. A plan line you cannot check is not a line.** Ten banned words that mark a line with no test ("carefully", "as appropriate", "if possible").
- **D5. The plan moves forward only.** Changes go into an append-only drift log; earlier units are never edited to look prescient.
- **D6. The plan does not replace the post-mortem.** It feeds it a fifth section, *plan vs fact*, written from the drift log.
- **D7. Three refusals:** the theatre plan, the plan that replaces thinking, the infinite plan with no stopping rule.
- **D8. A template** to copy, then delete what does not apply.
