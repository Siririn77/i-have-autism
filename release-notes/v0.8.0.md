# Release 0.8.0: code evals — three arms, executed tests

The behaviour suite scores prose. This one scores code: the answer's Python is written to disk and run
against a hidden unittest suite the model never sees. Only the interpreter decides.

## Three arms

| arm | system prompt |
|---|---|
| `none` | a neutral coding assistant |
| `graph` | graph first — root questions, nodes with anchors, typed edges, stop rule |
| `aggressive` | graph + coverage matrix (axes × stages) + register of what is left out |

Same user prompt everywhere, three samples per arm, majority decides, partial score is the mean fraction
of individual tests passed.

## The tasks

| case | requirements | what it catches |
|---|---|---|
| slugify | 7 | non-ASCII words, separator runs, whole-word truncation, one long word |
| chunked | 7 | empty input, string, generator, non-int and non-positive size |
| csv_line | 8 | quoted commas, escaped quotes, BOM, unclosed quote, text after a quote |
| merge_intervals | 7 | touching, nested, unsorted, invalid pair with numbers in the message |
| rate_limiter | 10 | lazy refill, capacity cap, atomic cost, injected clock, 200-thread race |

Four small tasks as controls, one dense. The contrast is the point.

## Result

| case | none | graph | aggressive |
|---|---|---|---|
| slugify | 3/3 | 3/3 | 3/3 |
| chunked | 3/3 | 3/3 | 3/3 |
| csv_line | 3/3 | 3/3 | 3/3 |
| merge_intervals | 3/3 | 3/3 | 2/3 |
| rate_limiter | 3/3 | 3/3 | 3/3 |
| cases, all three samples green | **5/5** | **5/5** | **4/5** |
| cases, majority green | 5/5 | 5/5 | 5/5 |
| tests | 1.00 | 1.00 | 0.93 |
| graph produced | 0/5 | 4/5 | 0/5 |
| matrix produced | 0/5 | 0/5 | 0/5 |

**On these tasks the graph changes nothing**, and **the aggressive instruction set was dropped
entirely**: zero matrices and zero registers in fifteen samples. A long instruction set loses to a short
concrete request.

## Four defects caught before the conclusion

Two in the tests, found by running reference implementations first:
`chunked` expected string slices where the spec promised lists; `csv_line` accepted text after a closing
quote, which rule 8 forbids. A correct implementation had failed both.

Two in the harness, found by reading the answers rather than the score:
a graph drawn in a plain-text fence was extracted as the code, so a correct answer scored zero with prose
as `solution.py`; and a 6000-token budget truncated the code after the graph, which made the graph arm
look worse for reasons unrelated to graphs. The extractor now reads the language tag; code cases get 9000
tokens.

Each of those four produced a "difference between arms" that was the instrument, not the model. That is
the usual way an A/B test lies.

## What it does not tell us

The tasks are too easy for this model: every arm solves them, so there is no headroom for a graph to
recover. The next honest step is a task whose requirement list is long enough that a competent
implementation still misses one — a config merger with fourteen interacting rules, a scheduler with
priority inversion, a migration with rollback and partial failure.

## Verify

```
python3 evals/calibrate_code_evals.py     # reference implementations pass every suite
python3 evals/run_code_evals.py --repeat 3 --workers 3
```
