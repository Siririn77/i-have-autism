# 0.15.0 — one command updates every copy

## The problem it removes

The ruleset lives in one file and is copied into seven clients: the Hermes plugin, the Cursor
always-on rule, the opencode package, two plain-text exports, and the plugin directory the running
agent actually reads. Each copy had its own build step. Editing a rule meant remembering four
commands and one copy step, and forgetting any of them produced the same quiet failure: a rule that
exists in the repository and not in the agent.

## The mechanism

```
python3 tools/update.py            # rebuild every copy, install into the profile, verify
python3 tools/update.py --bump X   # same, and set version X in every manifest
python3 tools/update.py --check    # change nothing; exit 1 on drift
```

Order is fixed and any failure stops the run naming the copy that did not update: builders, length
check against the 4500-character ceiling, install into the live plugin directory, then the builders'
own `--check` runs.

Two details that came out of building it:

- the version is read once per run, not per file. Reading it per file changed it halfway and the
  second manifest failed looking for a version that no longer existed;
- any version string in a manifest is replaceable, so a run that stopped halfway is repaired by
  running the same command again instead of by hand.

## Tests

`tests/test_update.py` runs the same command a maintainer runs and requires zero drift. 110 tests.
