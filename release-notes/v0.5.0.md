# Release 0.5.0: the graph before the plan

A plan orders units. It cannot order units you have not found. So the work now starts one step earlier:
with an **association graph** the plan is read off.

## What the graph is

- **Root questions first, one to five.** "Япония", "Гуадалканал", "Китай" are nodes, and all three sit on
  one axis. "Почему флот с превосходством потерял четыре авианосца за один день" is a root question.
  A graph grown from nouns is an encyclopedia; a graph grown from questions is an argument.
- **Four fields per node, or it is not a node:** what it is, why it matters to the reader, the anchor that
  proves it exists, and when or where. No anchor, no node — an unanchored node is a hypothesis and lives
  outside the graph.
- **Typed edges, four types, no others:** causes, contrasts, repeats, contradicts. "Related to" cannot be
  checked and cannot be cut, so it is decoration. A `contradicts` edge becomes a **fact gate** in the plan
  instead of a smoothed average.
- **Axes.** Every node lands on one. A node that lands on none either gets cut or creates a new axis — and
  a new axis means the frame is too narrow: stop and widen the frame, do not grow the graph.
- **A stop rule that is a decision.** Every root question has three answering nodes; every axis has three
  nodes; the next node would need an axis that does not exist. That converts "the topic is huge" into
  "the frame was wrong", which is a decision rather than a night of associations.
- **A budget.** One node is about one unit of work: three to five nodes inline for a one-liner, fifteen to
  thirty for a feature, forty to sixty per part for a film. Five hundred nodes on paper is cheaper to draw
  than four hundred are to throw away.
- **Conversion.** Every unit in the plan names the node id it serves. A node with no unit is a stated
  out-of-scope; a unit with no node is scope creep; a `contradicts` edge is a gate.

The file is `graph.md` next to `plan.md`: a Mermaid block that renders in GitHub, GitLab and Obsidian,
plus a node table (`id | what | why | anchor | when`) and an edge table (`from | type | to`).

## Why the rule is safe for small tasks

"Graph for every task" invites a diagram where a sentence was needed. The same rule forbids it: a
one-liner gets three nodes in the reply, no file, no Mermaid, no ceremony. One eval case exists only to
hold that line (`graph-does-not-swell-a-one-liner`).

## Evals

Three cases added; the suite is now 22 prompts, three samples per arm, majority verdict.

| case | without the rules | with the rules |
|---|---|---|
| `graph-backbone-series` | 0/3 | 3/3 |
| `graph-hypotheses-are-marked` | 3/3 | 3/3 |
| `graph-does-not-swell-a-one-liner` | 3/3 | 3/3 |

**Full suite: 16/22 without the rules, 22/22 with them.** The two guards tie by design: the model already
separates sourced facts from guesses, and it already answers a one-liner with a command. Their job is to
break loudly if a future edit loses that.

## Also in this release

- The compact always-on ruleset was rewritten to carry the graph rule inside the 4000-character cap:
  **29 rules, 3379 characters**. Code is now 11–18, Answers 19–25, exceptions 26–29.
- Sharpened in the previous commit and verified here: a verdict comes before the code sample, and a
  one-shot script gets its two or three plan lines in the reply with no file.
