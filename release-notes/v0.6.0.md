# Release 0.6.0: the graph toolkit

0.5.0 gave the graph a rule. This release gives it tools: a format that can be parsed, a checker that
fails loudly, a coverage report, a compiler that turns a graph into a plan skeleton, a diff for the drift
log, a renderer, and a scaffolder.

## The format

`references/graph-format.md` is the contract. A graph is one Markdown file: metadata, root questions,
one Mermaid block, a six-column node table (`id | что | ось | почему важно | подтверждено | когда`), a
four-column edge table (`от | тип | к | что это значит`), and an optional plan-mapping table.

**The tables are the source of truth; the Mermaid block is the drawing.** Both are written down and the
checker fails when they disagree — in either direction, node by node and edge by edge. A picture that
drifted from the table would be a lie the reader cannot see.

Russian type names are accepted (`причина`, `контраст`, `повтор`, `противоречие`) and normalised to
`causes`, `contrasts`, `repeats`, `contradicts`, so edges compare without a translation table in every
script.

## The six commands

| command | what it does |
|---|---|
| `graph_new.py "задача" --kind history` | the skeleton: metadata, five questions, axis presets by kind (history / code / lecture / fiction), empty tables |
| `check_graph.py graph.md` | ten rules, exit 1 on the first defect |
| `graph_stats.py graph.md` | answers per question, nodes per axis, longest cause chain, contradictions, nodes no unit cites |
| `graph_to_plan.py graph.md --out plan.md` | plan skeleton: a unit per mapping row, gates from every `contradicts`, out-of-scope for uncited nodes, an empty drift log |
| `graph_diff.py old.md new.md` | added, removed, retyped — the delta the drift log wants |
| `graph_render.py graph.md` | Mermaid block to PNG or SVG, using the Chromium already on the host |

## What the checker actually enforces

1. the file parses — six node columns, four edge columns, a Mermaid block;
2. every field is filled: **no anchor, no node**;
3. labels are unique — two nodes with one name cannot be told apart;
4. edges point at real nodes, carry a known type, are not self-loops or duplicates;
5. a `causes` edge never closes a cycle — a loop means a missing node or a wrong direction;
6. every node is reachable from a root question;
7. every root question has three answers (one is an opinion, three is a case);
8. every axis has three nodes (an axis with one node is a paragraph);
9. the Mermaid block and the tables agree;
10. the node count fits the declared budget.

## Worked on a real graph

The Second World War series: 5 root questions, 19 nodes, 46 edges, 5 axes, 3 contradictions that became
fact gates. `check_graph.py` → clean. `graph_stats.py` → the longest cause chain runs nine nodes
(N1 Versailles → … → N17 Yalta), which is the spine the series already follows. `graph_to_plan.py` →
a ten-part season skeleton with gates attached.

Two defects the tools found that the eye did not: a fifth question with only two answers, and an
`answers` relation drawn in Mermaid but missing from the table. Both are exactly the kind of drift a
picture hides.

## Packaging

The opencode package now ships `scripts/` and `references/` alongside `SKILL.md`, and a test fails if a
script exists in the skill but not in the package. A skill that calls six commands and ships none is a
rule with no tool.
