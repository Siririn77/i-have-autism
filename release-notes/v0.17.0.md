DeepSeek Harness: one more client reads the rules from the system prompt

`dsh/` is a Cordis bundle for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness). It
registers a single `ctx.systemPrompt` section at boot, so the ruleset is present before the first token
instead of being read on request like a skill.

- `dsh/lib/index.js` — `name`, `inject: ['systemPrompt']`, `apply(ctx)`; reads `rules.md` at boot and
  throws on a missing or empty file rather than registering an empty section.
- `dsh/cordis.patch.yml` — one `insert` row; `package.json` declares `dsh.bundle`, so
  `dsh plugin --profile <name> add file:$PWD/dsh` selects the layer by itself.
- `dsh/rules.md` — the same condensed core as every other always-on client, copied by
  `tools/build_dsh_plugin.py`, which `--check` fails on drift; the copy now runs inside
  `tools/update.py`.
- Off switch: `I_HAVE_AUTISM_OFF=1` for one run; `I_HAVE_AUTISM_RULES=<path>` swaps the ruleset.

Verified against `dsh` 0.2.2-rc.1 with a local Messages endpoint in place of the model: the section
appears in the request Harness actually sends, the off switch removes it from the same request, and a
deleted `rules.md` makes the entry fail to activate with a named error. Model behaviour under the rules
was not re-measured — the endpoint returned a fixed word.
